# 架构说明

## 运行链路

1. `启动型月搜索.bat` 或命令行启动 `app.server`。
2. `server.main()` 创建全局 `Store`，读取 `data/` 中的语料和索引。
3. `ThreadingHTTPServer` 在本机端口启动 `Handler`。
4. 页面通过 `/api/...` 请求搜索、定义、剧情、百科和官方问答数据。
5. 前端脚本将 JSON 结果渲染为搜索结果、阅读器或分类页面。

## 主要模块

- `app/core.py`：应用常量、查询规范化、文本片段和排序辅助。
- `app/store.py`：数据加载、索引构建和各查询入口。
- `app/http_server.py`：HTTP 路由和响应处理。
- `app/main.py`：服务启动。
- `app/server.py`：公共兼容门面，重新导出历史名称。
- `app/language_blocks.py`：混合语言恢复块的处理和读写。
- `app/multi_term.py`：多词查询拆分、组合匹配和最短路片段。
- `app/official_interviews.py`：官方问答提取、去重和答案摘要。
- `app/web/`：无需构建步骤的原生 HTML、CSS 和 JavaScript 页面。
- `tools/`：离线数据重建、结构导入和交叉验证工具。

## 数据加载

`Store` 初始化时主要读取：

- `corpus.txt` 与 `offsets.json`：正文和偏移索引。
- `entries.json`：词条、文档、别名和问答元数据。
- `story_blocks.json` 与 `jp_blocks.json`：中文剧情块和日文块。
- `occurrence_locations.json`：搜索结果可跳转的位置信息。
- `story.json`、`fgo_story.json` 和官方访谈索引：阅读器与官方资料结构。
- `aliases.json`、`query_rewrites.json`、`vocab.json`：查询规范化与联想。

## 搜索流程

1. 通过别名和查询重写规范化输入；别名只在完整查询（多词模式下为完整片段）与别名键一致时替换，不匹配更长词条中的子串。
2. 区分精确、标题包含、正文包含和多词组合匹配。
3. 使用固定作品顺序、资料类型和定义覆盖规则决定卡片顺序。
4. 为搜索结果生成有界片段和导航跳转信息。
5. 前端严格按照接口返回顺序渲染，不在客户端重新排序。

## 兼容入口

`app.server` 继续导出 `Store`、`Handler`、`main` 和核心名称；运行时 `STORE` 由 `app.store` 持有。新增调用应优先从 `app.store` 和 `app.http_server` 导入对应对象。

## 修改原则

- 不直接修改 `data/` 中的派生文件，优先修改重建工具后重新生成。
- 修改排序规则时必须增加最小回归测试，并检查稳定顺序。
- 修改 API 字段时同步检查 `app/web/`、`tests/` 和本文档。
- 正式改造前先备份，完成后再运行 Python、Node 和真实服务检查。
