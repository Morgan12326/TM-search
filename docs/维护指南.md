# 维护指南

## 开始前

1. 备份 `app/`、`data/` 和启动脚本。
2. 确认备份可以解压并启动。
3. 不在没有备份的情况下运行带 `--write` 的重建命令。
4. 检查原始语料目录仍然存在。

## 测试

```powershell
python -m compileall -q app tools tests
python -m unittest discover -s tests -v
node --test tests/test_render.mjs
```

从项目根目录执行。Python 测试依赖完整 `data/`；部分集成测试还需要原始语料目录。

## 重建顺序

推荐顺序：

1. `tools/rebuild_source_data.py`
2. `tools/rebuild_occurrence_index.py`
3. `tools/rebuild_interview_index.py`
4. 作品专用脚本：`rebuild_fha_story.py`、`rebuild_fsf_story.py`
5. 使用 `tools/verify_occurrence_index.py` 和 `tools/verify_live_fgo_story.py` 验证

具体参数以各脚本的 `--help` 为准。脚本的 `--write` 会修改 `data/`，执行前必须确认备份。

## 修改检索或排序

- 先定位 `app/core.py`、`app/store.py` 和 `app/http_server.py` 中对应的常量、匹配函数、排序方法和路由。
- 优先添加最小失败测试，再修改实现。
- 不要依赖偶然的字典顺序；明确使用排序键。
- 检查精确匹配、标题包含、正文包含、多词和官方结果是否互相影响。
- 完成后同时运行 Python 和 Node 测试，并通过真实 HTTP 服务检查代表性查询。

## 故障排查

- 页面无法启动：检查 Python 版本、端口占用和 `data/corpus.txt` 是否存在。
- 搜索无结果：检查 `entries.json`、`offsets.json` 和同编号的正文数据。
- 跳转位置错误：重新检查 `occurrence_locations.json` 与 `story.json`。
- 测试导入失败：从项目根目录运行测试，不要从 `tests/` 内部单独执行。
